화면 확인은 안전하게,
결과물은 새 창으로

AI가 "잘 됐나" 화면을 찍어 보다가 내가 쓰던 크롬 창을 통째로 닫고, 작업 중인 화면 전체를 찍어 버린 일이 있었다. 그 뒤로 정한 규칙이다. 확인은 캡처 전용 브라우저로만 하고, 보여 줄 때는 새 창만 연다.

화면 확인 헤드리스 브라우저 안전 규칙 2026.10 기준

이 노트를 읽고 나면

"사람이 쓰는 화면은 건드리지 않는다."

  • ✓AI의 화면 확인이 왜 내 브라우저를 망가뜨릴 수 있는지 안다.
  • ✓캡처 전용 브라우저 + 매번 새 프로필로 확인하는 법을 안다.
  • ✓결과물을 "새 창으로만" 보여 주는 이유를 안다.
  • ✓완성본만 띄우고 중간 파일은 경로만 알려 주는 기준을 안다.

01 — 실제로 있었던 사고 3건

모두 9월, 모두 "확인하려다" 생겼다.

1

9/8 — 크롬이 통째로 꺼짐

확인을 마치고 정리하는 명령이 "크롬"이라는 이름의 프로그램을 전부 꺼 버렸다. 내가 쓰던 창도 같이 꺼졌다.

2

9/12 — 화면 전체가 찍힘

방금 띄운 창만 찍으려고 화면 캡처 명령을 썼는데, 실제로는 모니터 전체가 찍혔다. 작업 중이던 다른 창들이 그대로 사진에 남았다.

3

9/17 — 열려 있던 크롬 창이 전부 닫힘

화면 없이 도는 크롬(헤드리스)을 전용 프로필 없이 실행했다. 이 크롬이 평소 쓰던 프로필을 잡아채면서 열려 있던 창이 모두 닫혔다. "크롬 창 가져간 게 너야?"라는 질문으로 발견됐다.

같은 날(9/17) 결과물을 그냥 "열기" 명령으로 띄웠더니 다른 화면(데스크톱 공간)의 창에 붙어서 보이지도 않았다. 보여 주는 방법도 같이 바꿔야 했다.

02 — 원인: 사람과 AI가 같은 크롬을 썼다

세 사고의 뿌리는 하나.

프로필 공유

같은 사용자 정보

크롬은 프로필(로그인·탭·창 정보) 하나를 한 번에 한 프로그램만 쓴다. AI가 그걸 잡으면 사람 쪽이 밀려난다.

화면 캡처

찍는 범위가 화면 전체

운영체제의 화면 캡처는 "내가 띄운 창"을 모른다. 보이는 것을 다 찍는다.

정리 명령

이름으로 끄기

"크롬"이라는 이름으로 끄면 내 크롬과 AI 크롬을 구분하지 못한다.

03 — 확인은 '캡처 전용 브라우저'로

사람의 크롬과 완전히 떨어진 별도 브라우저.

1. 전용 브라우저진짜 크롬 앱이 아닌 캡처 전용 셸
2. 새 프로필호출마다 빈 임시 프로필
3. 고유 이름결과 파일에 세션 표식
4. 직접 보기찍힌 사진을 열어 확인
5. 자기 것만 정리내가 띄운 것만 끈다
  • 진짜 크롬 앱으로는 절대 찍지 않는다. 실행 중 "Google Chrome"으로 등록돼 다른 명령이 그쪽으로 붙을 수 있다.
  • 프로필 폴더와 결과 파일 이름에 세션 고유 표식을 붙인다. 공용 이름(예: 같은 임시 폴더 이름)을 쓰던 시절엔 다른 창의 결과와 섞여 엉뚱한 화면이 찍힌 적이 있다.
  • 폰(390)·PC(1280) 두 크기로 찍고, 사진을 직접 연다. "찍었습니다"가 아니라 "봤더니 이렇습니다"가 확인이다.

04 — 보여 주기는 '새 창'으로

쓰던 창·탭은 건드리지 않는다.

하지 않는 것대신 하는 것
파일을 그냥 "열기"크롬에 "새 창으로 열어 줘" 요청만 보낸다.
쓰던 창을 앞으로 가져오기 · 탭 추가쓰던 창은 그대로 두고 새 창 하나만 만든다.
화면 캡처로 확인캡처 전용 브라우저의 스크린샷으로 확인한다.
크롬을 이름으로 강제 종료내가 띄운 프로세스와 임시 프로필만 정리한다.

새 창 도구는 결과를 네 가지로 솔직하게 알려 준다 — 앞에 떴음 / 뒤에 떴음 / 실패 / 이미 열려 있음. "띄웠습니다"라고 말하기 전에 이 결과를 본다.

05 — 완성본만 띄우고, 중간 파일은 경로만

창이 많아지면 그것도 방해다.

띄운다

완성 결과물

보고서, 고르기 페이지, 확정 시안처럼 "지금 봐 주세요"인 것만.

경로만

중간 산출물 · 참고 파일

작업 중 버전, 근거 자료는 파일 위치만 알려 준다.

창을 띄워도 채팅에 핵심 요약과 파일 경로를 같이 적는다. 창이 다른 화면에 떠서 못 볼 수도 있기 때문이다.

06 — 규칙만으론 부족하다

문서에 적은 금지는 잊힌다.

세 사고를 막는 금지 규칙은 처음엔 문서에만 있었다. 그런데 규칙이 생긴 뒤에도 옛 문장을 따르거나 창을 앞으로 가져오는 위반이 다시 나왔다. 그래서 명령이 실행되기 직전에 자동으로 걸러 내는 장치(훅)를 만들어 시험 327개를 통과시켰다. 이 장치는 AI가 스스로 켤 수 없게 되어 있어서, 사람이 직접 켜는 단계가 남아 있다.

📚 더 깊이 — 강의용 상세

탭을 눌러 펼쳐 보세요.

'헤드리스'와 '프로필'

헤드리스 브라우저는 화면에 창을 띄우지 않고 속에서만 페이지를 그리는 브라우저다. 사진을 찍거나 버튼을 눌러 보는 자동 확인에 쓴다. 문제는 진짜 크롬을 헤드리스로 돌리면, 따로 말하지 않는 한 평소 쓰는 프로필을 쓰려 한다는 점이다.

프로필은 크롬의 "사용자 서랍"이다. 로그인, 열린 창, 탭이 다 여기 들어 있다. 한 서랍은 한 번에 한 프로그램만 열 수 있다. 그래서 확인용 브라우저에는 매번 새 빈 서랍(임시 프로필)을 주고, 아예 진짜 크롬이 아닌 캡처 전용 브라우저를 쓴다.

페이지 하나를 고친 뒤 — 확인에서 보여 주기까지

  • 1) 스크립트 문법 검사를 돌린다.
  • 2) 캡처 전용 브라우저로 폰·PC 크기 사진을 찍는다(새 임시 프로필, 고유 이름).
  • 3) 사진을 직접 열어 깨진 곳이 없는지 본다. 버튼이 있으면 눌러 보는 시험도 한다.
  • 4) 다 괜찮으면 완성본만 새 창 도구로 띄운다.
  • 5) 결과(앞에 떴음/뒤에 떴음/실패)를 보고, 채팅에 요약과 경로를 적는다.

이런 데서 자주 사고가 난다

  • ① 프로필 옵션을 빠뜨림. 헤드리스라도 평소 프로필을 잡는다. → 크롬 실행 명령에는 예외 없이 전용 프로필.
  • ② "내 창만 찍으면 되겠지". 화면 캡처는 화면 전체를 찍는다. → 캡처 전용 브라우저의 스크린샷만.
  • ③ 이름으로 정리. 크롬 전체가 꺼진다. → 내가 띄운 것만, 고유 표식으로.
  • ④ 그냥 열기. 어느 창에 붙을지 모른다. → 새 창 요청만.
  • ⑤ 중간 파일까지 다 띄움. 창이 쌓여 오히려 방해. → 완성본만.

내 환경 점검 (3분)

  • AI가 브라우저를 실행하는 명령에 전용 프로필이 늘 붙어 있나?
  • 결과 사진·임시 폴더 이름에 세션 고유 표식이 있나?
  • "끄기·정리" 명령이 이름이 아니라 내가 띄운 것만 대상으로 하나?
  • 결과물을 보여 줄 때 새 창으로만 여나?
