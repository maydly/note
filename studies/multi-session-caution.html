Claude 창 여러 개를
동시에 쓸 때 주의할 것

편집기를 전체 화면으로 띄우고 Claude 창을 여러 개 열어 일하면 빠르다. 최근 30일만 해도 작업 창이 126개였다. 그런데 창들은 서로를 모른 채 같은 파일·같은 저장소·같은 브라우저를 쓴다. 실제로 부딪힌 일과 막는 방법을 정리했다.

멀티 세션 충돌 방지 git 2026.10 기준

이 노트를 읽고 나면

창끼리는 서로 대화하지 않는다.

  • ✓여러 창이 무엇을 함께 쓰고 있는지 안다.
  • ✓실제로 부딪히는 다섯 가지 상황과 막는 법을 안다.
  • ✓세션 고유 이름과 잠금으로 충돌을 피하는 법을 안다.
  • ✓창마다 작업 영역을 나누는 습관을 들인다.

01 — 창들이 함께 쓰는 것

창은 따로여도 컴퓨터는 하나.

파일

같은 폴더 · 같은 파일

두 창이 같은 파일을 고치면 나중에 저장한 쪽이 앞의 것을 덮는다.

저장소

같은 git 저장소

올릴 준비 칸(스테이징)과 잠금 파일을 함께 쓴다.

임시 폴더

같은 임시 공간

같은 이름의 임시 파일을 쓰면 서로의 결과를 덮는다.

계정

같은 로그인 상태

GitHub 명령 도구의 "지금 계정"은 컴퓨터 전체에 하나다.

브라우저

같은 크롬

사람이 쓰는 크롬 프로필을 창들이 잡으려 하면 사고가 난다.

02 — 실제로 부딪히는 5가지

겪은 일 → 막는 법.

상황일어난 일막는 법
임시 이름 충돌여러 창이 같은 이름의 캡처 폴더를 쓰다가 다른 창의 화면이 찍혔다.모든 임시 파일·폴더에 세션 고유 표식.
계정 전환 경쟁맞지 않는 계정으로 올리면 거부(403)된다. 계정 전환은 컴퓨터 전체에 적용돼서, 한 창이 바꾸면 다른 창의 올리기에도 영향을 준다.잠금을 건 뒤 전환 → 올리기 → 원래 계정 복원.
먼저 올라간 변경다른 곳에서 먼저 올린 변경이 있어 "fetch first"로 올리기가 거부됐다.올리기 전에 최신을 받고, 뒤처져 있으면 올리지 않는다.
남의 변경이 커밋에 섞임다른 창이 준비 칸에 올려 둔 파일까지 같이 커밋될 수 있다.커밋할 파일을 직접 지정한다.
크롬 프로필 공유확인용 크롬이 사람의 프로필을 잡아 열린 창이 전부 닫혔다.캡처 전용 브라우저 + 매번 새 임시 프로필.

03 — 세션 고유 이름

이름만 달라도 대부분의 충돌이 사라진다.

창(세션)마다 고유한 번호가 있다. 그 앞 몇 자리를 임시 폴더·결과 파일·브라우저 프로필 이름에 붙인다. 공용 이름을 쓰지 않는 것만으로 서로의 결과를 덮는 일이 없어진다.

/tmp/cc_<세션 앞 8자리>_작업이름/      ← 임시 작업 폴더
<세션 앞 8자리>_<시각>_화면이름.png      ← 캡처 결과
프로필: /tmp/cc_<작업>_prof_<표식>      ← 확인용 브라우저 전용
정리도 고유 표식으로만. 끝나고 지울 때 "크롬", "캡처" 같은 일반 이름으로 지우거나 끄면 다른 창의 것까지 사라진다. 내가 만든 표식이 붙은 것만 정리한다.

04 — 잠금: 한 번에 한 창만

공용 상태를 바꾸는 일에는 줄을 세운다.

계정 전환처럼 컴퓨터 전체에 하나뿐인 것을 바꾸는 도구, 버전 파일을 만드는 도구에는 잠금을 걸었다. 폴더 만들기는 "이미 있으면 실패"하므로 잠금으로 쓰기 좋다.

if mkdir /tmp/cc_push.lock 2>/dev/null; then
  # 계정 전환 → 올리기 → 원래 계정 복원
  rmdir /tmp/cc_push.lock
else
  echo "다른 창이 올리는 중 — 잠시 뒤 다시"
fi

05 — git 습관 세 가지

여러 창 · 여러 기기에서 공통.

1

먼저 받기

올리기 전에 원격의 최신을 받는다. 뒤처져 있으면 올리지 않고 먼저 합친다.

2

파일 지정 커밋

"전부 커밋" 대신 이번에 바꾼 파일만 지정해서 커밋한다. 다른 창의 작업이 섞이지 않는다.

git commit -m "메시지" -- 바꾼파일1 바꾼파일2
3

작업 사본은 동기화 폴더 밖에

사이트 저장소는 클라우드 동기화 폴더가 아닌 곳에 따로 받아 작업한다. 동기화 폴더 안 저장소는 손상된 적이 있다.

06 — 창마다 작업 영역 나누기

가장 확실한 방법은 애초에 겹치지 않게.

  • ✓창 하나에 업무 하나. 같은 파일을 두 창에서 고치지 않는다.
  • ✓같은 저장소를 두 창이 쓰면, 올리기는 한 창에서만 한다.
  • ✓오래 쉬었다 돌아온 창은 먼저 상태(바뀐 파일·최신 여부)를 확인하고 이어 간다.
  • ✓새 일은 새 창에서 시작한다. 긴 대화 하나에 여러 일을 쌓지 않는다.

왜 창끼리 부딪히나 — '공용 상태'

각 Claude 창은 자기 대화만 기억한다. 다른 창이 무엇을 하는지는 모른다. 그런데 파일, git 저장소, 임시 폴더, 로그인 계정, 브라우저 프로필은 컴퓨터에 하나씩만 있는 공용 상태다.

공용 상태를 두 창이 동시에 바꾸면 순서에 따라 결과가 달라진다. 해결책은 세 가지다. 이름을 나누거나(고유 표식), 줄을 세우거나(잠금), 영역을 나누는 것(창마다 다른 일).

두 창이 같은 사이트를 고칠 때 — 안전한 순서

  • 1) 창 A는 노트 본문, 창 B는 목차 페이지처럼 파일을 나눈다.
  • 2) 각 창은 자기 파일만 지정해서 커밋한다.
  • 3) 올리기는 한 창에서만. 올리기 전 최신을 받는다.
  • 4) 계정을 바꿔 올려야 하면 잠금 → 전환 → 올리기 → 복원 순서를 도구로 고정한다.
  • 5) 올린 뒤 실제 공개 주소에서 두 창의 변경이 모두 보이는지 확인한다.

이런 데서 자주 부딪힌다

  • ① 공용 임시 이름. /tmp/shot.png 같은 이름. → 세션 고유 표식.
  • ② 전부 커밋. 다른 창 작업까지 섞인다. → 파일 지정.
  • ③ 이름으로 정리. 다른 창의 브라우저·파일까지 지운다. → 내 표식만.
  • ④ 받지 않고 올리기. 거부되거나 남의 변경을 덮을 위험. → 먼저 받기.
  • ⑤ 오래된 창 그대로 이어 쓰기. 그사이 다른 창이 바꾼 걸 모른다. → 상태 확인부터.

지금 열린 창 점검 (3분)

  • 지금 열린 창들이 각각 무슨 일을 하는지 한 줄씩 적을 수 있나?
  • 같은 파일·같은 저장소를 쓰는 창이 둘 이상인가?
  • 그렇다면 올리기를 맡을 창 하나를 정한다.
